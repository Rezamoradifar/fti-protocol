# تست مسیر کاربر روی همان تست‌نت فعال

این ابزار برای دیپلوی تازهٔ `bc2163070a6e79bcc129a6a788e61c4ace402bdf` روی شبکهٔ ۹۷ و آدرس باینری `0x40e727e15b65461D52e92907aa96E27017Ea70fE` آماده شده است. قرارداد تازه نمی‌سازد و سایت یا Keeper را جابه‌جا نمی‌کند. ابزار، source fingerprint، bytecode، اسلات implementation، تراکنش‌های ایجاد و اتصال قراردادها را قبل از ارسال بررسی می‌کند.

دستیار به SSH متصل نیست؛ تراکنش عمومی این سناریو هنوز توسط دستیار انجام نشده است. فرمان زیر را اپراتور روی VPS فعلی اجرا می‌کند. اجرای موفق محلی، نتیجهٔ عمومی تست‌نت نیست.

پرداخت ماهانهٔ واقعی رنک، تغییر حاکمیت و امضای کیف‌پول در رابط مرورگر در این سناریوی عمومی انجام نمی‌شوند. قواعد ماهانه/اتوبای رنکی/حاکمیت در تست‌های محلی جدا بررسی می‌شوند. موجودی فعلی استخر عمومی با واجدین شرایط جدید طبق همان قواعد تقسیم خواهد شد؛ تست، استخر اختصاصی جدیدی ایجاد نمی‌کند.

## هزینه و نگهداری

- سقف مجموع گس تراکنش‌های ابزار و شارژ چهار کیف‌پول: **۰٫۰۳ tBNB**؛ سقف قیمت گس: **۰٫۱ gwei**. هر کیف‌پول جدید ۰٫۰۰۲ tBNB می‌گیرد. شمارش بودجه محافظه‌کارانه است: هم مبلغ شارژ و هم گس مصرفی حساب‌های تست را حساب می‌کند. گس Keeper فعلی در این بودجه نیست.
- منبع گس، فایل خصوصی موجود `/root/.fti-private/testnet-deployer.key` است. آدرس آن باید همان deployer تأییدشده و متفاوت از Keeper باشد؛ در غیر این صورت ابزار پیش از ارسال متوقف می‌شود. کلید در خط فرمان، GitHub و گزارش چاپ نمی‌شود.
- journal شامل کلیدهای آزمایشی و تراکنش امضاشده است و در پوشهٔ root با مجوز ۰۷۰۰ و فایل ۰۶۰۰ نگهداری می‌شود. فقط **report.json** قابل اشتراک است. ماندهٔ تست در کیف‌پول‌های جدید حفظ می‌شود.
- آزمون پس از تأیید `TEST 97` در یک سرویس جدا و موقت systemd اجرا می‌شود. قطع SSH مانع ادامه نیست. قفل کرنل اجازهٔ اجرای هم‌زمان دو worker را نمی‌دهد. قطع RPC یا کمبود گس می‌تواند اجرای ناقص ایجاد کند؛ journal را نگه دارید و همان دستور را دوباره اجرا کنید. به‌صورت خودکار بودجه افزایش نمی‌یابد.
- زمان بسته‌شدن واقعی ساعت جلو برده نمی‌شود؛ در حالت معمول انتظار می‌تواند تا حدود یک ساعت باشد. کندی Keeper یا شبکه هم قابل تشخیص است. انتظار هر مرحله محدود به دو ساعت است.

## فرمان کامل روی سرور

در بررسی عمومی این نوبت، `/health` پاسخ ۲۰۰ داد اما `/api/events` و `/api/market` پاسخ ۵۰۳ دادند. درخواست مستقل `eth_getLogs` به دو RPC عمومی BNB نیز خطای `-32005 limit exceeded` برگرداند. این شاهد، نشانی و علت دقیق خطای EVENT_RPC خصوصی سرور را مشخص نمی‌کند. بنابراین ابزار پیش از هر شارژ آزمایشی، قابلیت خواندن لاگ را بررسی می‌کند و اگر در دسترس نباشد هیچ تراکنش تست جدیدی نمی‌فرستد.

اگر RPC تست‌نتِ دارای `eth_getLogs` در اختیار دارید، URL آن را فقط روی سرور در فایل `/root/.fti-private/testnet-journey-rpc.url` با مالک root و مجوز ۰۶۰۰ ذخیره کنید. فرمان زیر این فایل را برای **ابزار تست** استفاده می‌کند؛ تنظیمات سایت/Keeper را عوض نمی‌کند. بدون این فایل، RPC موجود سرویس استفاده می‌شود. این قابلیت با گزینهٔ `--rpc-file` پیاده شده و کلید API در آرگومان یا خروجی قرار نمی‌گیرد. تا دریافت گزارش واقعی موفق، مرحلهٔ عمومی این تست تکمیل‌شده اعلام نمی‌شود.

```bash
(
  set -euo pipefail
  umask 077
  FTI_TEST_DIR=$(mktemp -d /root/fti-live-tests.XXXXXXXX)
  FTI_TEST_BASE='https://raw.githubusercontent.com/Rezamoradifar/fti-protocol/53f764fed3846dc2c733e74d9454cf8c4f865e20/tools'
  for FTI_TEST_FILE in run-fresh-testnet-journey.py fresh-testnet-journey.mjs; do
    curl --proto '=https' --tlsv1.2 -fL --retry 2 --connect-timeout 15 --max-time 90 \
      "$FTI_TEST_BASE/$FTI_TEST_FILE" -o "$FTI_TEST_DIR/$FTI_TEST_FILE"
  done
  printf '%s  %s\n' \
    'a58bece4d9948d014c561cf4230d6bba421488feab81c6aaaa535c9a4418a90a' "$FTI_TEST_DIR/run-fresh-testnet-journey.py" \
    'd0fd6574e43e58162263a70f96280350f0e865a9198d11de1828551080ab079f' "$FTI_TEST_DIR/fresh-testnet-journey.mjs" | sha256sum -c -
  FTI_TEST_ARGS=()
  if [ -s /root/.fti-private/testnet-journey-rpc.url ]; then
    FTI_TEST_ARGS=(--rpc-file /root/.fti-private/testnet-journey-rpc.url)
  fi
  python3 "$FTI_TEST_DIR/run-fresh-testnet-journey.py" "${FTI_TEST_ARGS[@]}"
)
```

برنامه پیش از شروع، شبکه، قرارداد، کیف‌پول گس و سقف هزینه را نمایش می‌دهد. برای اجرای همان تست‌های نمایش‌داده‌شده `TEST 97` وارد کنید. مجوز قبلی دیپلوی هشت تراکنش، برای هزینهٔ این سناریوی جدید استفاده نمی‌شود.

مشاهدهٔ پیشرفت:

```bash
journalctl -u fti-testnet-journey -n 40 --no-pager
```

نشانهٔ موفقیت `FTI_TESTNET_JOURNEY_PASS` است. `FTI_TEST_STARTED` فقط شروع کار است. نتیجه در مسیر زیر نوشته می‌شود:

```
/root/.fti-fresh-journey/0x40e727e15b65461d52e92907aa96e27017ea70fe/report.json
```

## شواهد آزمون ابزار

- `node --test test/fresh-testnet-journey.test.mjs`: دو آزمون موفق؛ یک آزمون سیاست مقصد/بودجه و یک آزمون EVM کامل با اثبات توقف پیش از شارژ حساب‌ها هنگام قطعی RPC تاریخچه، با استخر قبلیِ غیرصفر، قطع عمدی پیش از ارسال، ادامهٔ همان تراکنش، تمام مسیر کاربر و اجرای مجدد بدون تراکنش تکراری. آخرین اجرای مستقل حدود ۴۹ ثانیه بود.
- `python3 -B test/fresh-testnet-journey-launcher.test.py -v`: پنج آزمون موفق؛ لغو پیش از ارسال، جلوگیری از worker دوم، شروع جداگانه بدون افشای RPC در آرگومان/خروجی، رد hash نادرست و رد فایل کلید اشتراکی/symlink. systemd در این آزمون‌ها شبیه‌سازی شده و اجرای واقعی VPS نیست.
- `node --check tools/fresh-testnet-journey.mjs` و بررسی نحو پایتون موفق هستند. هر دو فایل منتشرشده از URL ثابت بالا دوباره دانلود و SHA-256 آن‌ها تطبیق داده شد.
- هیچ فایل قرارداد، فرانت یا منبعی که fingerprint دیپلوی فعال را می‌سازد تغییر نکرده است. ابزار خارج از release فعال اجرا می‌شود.
