# نصب چیدمان جدید FTI روی سرویس موجود

این مسیر، بستهٔ قبلاً تحویل‌شدهٔ `FTI-organized-workspace-20261012.zip` را نصب می‌کند. خود ZIP باید ابتدا از فایل تحویل‌شده در گفتگو به سرور منتقل شود؛ این نصب‌کننده ZIP را از گیت‌هاب دریافت نمی‌کند. کد کامل تغییرات هنوز به فایل‌های frontend این شاخه merge نشده است. فایل جدید این شاخه، نصب‌کننده و راهنمای آن است. استفاده از بستهٔ محلی اجباری است و بدون آن فرمان موفق گزارش نمی‌شود.

## فایل ورودی

با ابزار انتقال فایل SSH/SFTP، فایل ZIP را بدون استخراج و بدون بازفشرده‌سازی در مسیر زیر قرار دهید:

`/root/FTI-organized-workspace-20261012.zip`

SHA-256 فایل ورودی: `31233959d50bffa8a992d34542673fcb661deba917d11cd45f96a81827934ef7`.

این بسته شامل حذف دکمهٔ اتصال کیف‌پول تکراری، بخش مشترک خرید/فروش/انتقال، ترتیب کاربردی صفحهٔ اول، فارسی در انتهای فهرست زبان، نمودار منحنیِ مشاهدات و دکمه‌های اشتراک تلگرام/X و لینک GitHub است. لینک کانال یا حساب اجتماعیِ ارائه‌نشده ساخته نمی‌شود؛ اشتراک‌گذاری با دنبال‌کردن حساب رسمی متفاوت است. ترجمهٔ همهٔ متن‌های تفصیلی و راه‌اندازی قرارداد جدید جزو این نصب نیست.

## فرمان نصب

روی همان سرور با root:

```bash
(
  set -euo pipefail
  umask 077
  PACKAGE='/root/FTI-organized-workspace-20261012.zip'
  if [ ! -f "$PACKAGE" ]; then
    echo 'PACKAGE_MISSING: upload FTI-organized-workspace-20261012.zip to /root first.' >&2
    exit 1
  fi
  printf '%s  %s\n' '31233959d50bffa8a992d34542673fcb661deba917d11cd45f96a81827934ef7' "$PACKAGE" | sha256sum -c -
  REV='5ee3ebf19d76b543d29f41737143b36e832f2541'
  FILE="$(mktemp /root/fti-organized.XXXXXX.py)"
  curl -fL --retry 2 --connect-timeout 15 --max-time 120 \
    "https://raw.githubusercontent.com/Rezamoradifar/fti-protocol/$REV/tools/install-organized-frontend.py" -o "$FILE"
  printf '%s  %s\n' '47428289b45ba337a8ee8f6f91a4ee1f7c9f66c461fa154c3d6f07236b382940' "$FILE" | sha256sum -c -
  printf '\nINSTALLER_SAVED=%s\n' "$FILE"
  python3 -I "$FILE" --port 3110 --package "$PACKAGE" --apply
)
```

## عملکرد و مرزها

نصاب فقط سرویس مستقیم و شناخته‌شدهٔ 3110 با مدل Continuity و chainId=97 را می‌پذیرد. نسخهٔ Node سرویس باید حداقل 22 و وابستگی‌های موجود مطابق قفل بازبینی‌شده باشند. helper نصب قبلی از commit ثابت دریافت و پیش از استفاده با SHA-256 کنترل می‌شود. کد ورودی خام ناشناس اجرا نمی‌شود. ورودی‌های پایه از commit ثابت `530e993957459cbc94a5b403d9b819171df19f8f` و ۱۷ فایل تأییدشده از ZIP در پوشهٔ خصوصی مستقل ترکیب می‌شوند. دو فایل Solidityِ همان مبنا فقط برای آزمون عدم تغییر منطق مالی در آن پوشه خوانده می‌شوند؛ روی قرارداد نصب‌شده هیچ عملیاتی انجام نمی‌شود.

پنل و لندینگ ساخته می‌شوند، ۳۸ تست قبلی و ۱۹ تست چیدمان اجرا می‌شوند و تمام ۹ فایل خروجی باید با SHA-256 جدیدِ ازپیش بررسی‌شده مطابقت کنند. این مرحله نباید با گذر از hash قدیمی یا جعل sourceFingerprint نصب فعال اشتباه شود: backendRevision و فایل‌های حفاظت‌شدهٔ نصب قبلی عوض نمی‌شوند. شناسهٔ فرانت جدید محتوایی است، نه یک commit ساختگی: `organized-20261012-cc7e572c1116`.

فقط HTML ورودی پنل و لندینگ به فایل‌های ثابتِ نسخه‌دار جدید وصل می‌شوند. استایل تم قبلی و فرانت جهانی قبلی نیز به‌عنوان مبدأ شناخته‌شده پذیرفته می‌شوند. فایل ناشناخته، تغییر هم‌زمان، مسیر symlink، مغایرت HTTP یا hash باعث توقف می‌شود. npm install، git pull، restart، تنظیم nginx، خواندن .env، کلید، دیپلوی، ارتقا یا مهاجرت انجام نمی‌شود. پورت 3108 دست‌نخورده می‌ماند. آدرس دامنه باید از قبل به همین سرویس وصل باشد.

نتیجهٔ موفق در خروجی `FTI_ORGANIZED_FRONTEND_INSTALLED` یا برای نصب تکراری `FTI_ORGANIZED_FRONTEND_ALREADY_INSTALLED` است. `contractsChanged`، `servicesRestarted` و `fundsMoved` برابر false هستند. مسیر `backup` و `INSTALLER_SAVED` را نگه دارید. فایل ساخت و log خصوصی زیر `/var/backups/fti-global-frontend/organized-build-...` باقی می‌مانند. این محل جای بکاپ کاربران یا نسخهٔ خارج از سرور نیست.

در صورت نیاز، با مسیر واقعی چاپ‌شدهٔ نصب‌کننده و بکاپ برگردید:

```bash
python3 -I /root/ACTUAL_INSTALLER.py --port 3110 --restore /var/backups/fti-global-frontend/ACTUAL_BACKUP
```

بازگشت به ZIP نیاز ندارد، ولی helper ثابت را از گیت‌هاب می‌خواند. هر HTML جداگانه اتمیک جایگزین می‌شود؛ این دو فایل یک تراکنش مشترک نیستند. خطای معمولِ نصب، HTMLهای همین نصب را برمی‌گرداند؛ ویرایش هم‌زمان مدیر بازنویسی نمی‌شود. قطع برق یا SIGKILL ممکن است به اجرای restore نیاز داشته باشد. این rollback فقط فرانت است، نه بلاک‌چین.

## شواهد همین نوبت

- فایل منتشرشدهٔ نصب‌کننده با Git blob `94797efacd7b971917b9d67191900358b1df88cc` و SHA-256 فرمان بالا تطبیق داده شد.
- ۵۷ تست فرانت/پوسته/چیدمان در محیط محلی دوباره اجرا شدند: صفر شکست/لغو/skip.
- ۲۹ آزمون نصب، hashها، رد بستهٔ تغییرکرده، فایل‌های خصوصی، خطای HTTP، ویرایش هم‌زمان، نصب تکراری، نصب روی تم قبلی و فرانت جهانی قبلی و بازگشت دقیق موفق بودند. transport این آزمون‌ها شبیه‌سازی‌شده است، نه اثبات کارکرد VPS کاربر.
- ساخت واقعی جداگانه از ورودی پایه و همان ZIP اجرا شد؛ ۵۷ تست و تطبیق بایت‌های هر ۹ فایل خروجی موفق شدند. دو fixture منطق مالی ابتدا در پوشهٔ تست نبودند و تست عدم تغییر قرارداد شکست خورد؛ fixtureهای ثابتِ تأییدشده اضافه و کل بررسی با موفقیت دوباره اجرا شد. تست حذف یا ضعیف نشد.
- دریافت مستقیم اینترنت در محیط توسعه به علت DNS برقرار نبود. پایهٔ ساخت از artifact خوانده‌شدهٔ گیت‌هاب بازسازی شد؛ source hashها بررسی شدند. دانلود واقعی روی VPS و نصب روی دامنهٔ کاربر هنوز مشاهده نشده است. نتیجهٔ CI جدید برای این wrapper یا اجرای همهٔ تست‌های مخزن ادعا نمی‌شود.

این انتشار، دستور نصب همین بستهٔ فرانت است؛ قرارداد تازه را دیپلوی نمی‌کند و قابلیت اتوبای یا منطق تسویه را به قرارداد قدیمی اضافه نمی‌کند.
