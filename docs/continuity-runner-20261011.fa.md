# ادامهٔ FTI: اجرای ایزولهٔ تست حفظ کاربران و صندوق‌ها

## محدودهٔ تغییر

این اصلاح فقط ابزار اجرای تست و تست‌های همان ابزار را تغییر می‌دهد. قراردادها، کارمزدها، قوانین باینری، اختیارات شورا، آدرس‌های نصب‌شده، سرویس وب و Keeper دست‌نخورده‌اند. این نسخه ابزار انتقال پول به آدرس جدید یا اجرای ارتقا نیست.

مبنای کد بررسی‌شده: `b254a379b08929a261dccfeae18bcf17d3781b90` از PR #18.

## شواهد بررسی‌شده

اجرای GitHub Actions شمارهٔ `38081278472`، job شمارهٔ `114298531973` در ۱۰ اکتبر ۲۰۲۶ با موفقیت تمام شد. لاگ کامل، ۱۶۵ تست موفق و صفر failure/cancel/skip را نشان می‌دهد. Checkout این اجرای PR روی merge آزمایشی `efe03d2585c947754fbfc2859c03df825ddef438` بوده است؛ این SHA را با SHA شاخه یکسان تلقی نکنید.

تست محلی EVM حفظ وضعیت هنگام ارتقا، ۳۱ عضو، ۳۲ دارندهٔ توکن، ۲۶۱۰ testUSD مطالبات نقدی، ۹۰ testUSD خرید خودکار معوق و رد ۲۹ حالت خرابی را ثبت کرده است. پرداخت نقدی و خرید خودکارِ یک‌باره، انتقال با allowance، خرید، فروش، ثبت‌نام جدید و خرید چندباره پس از ارتقا در همان تست بررسی شده‌اند. این اعداد مربوط به داده‌های آزمایش‌اند، نه موجودی یا پرداخت مشاهده‌شده روی BNB Testnet.

لاگ نصب همان اجرا هنوز ۳۶ هشدار وابستگی شامل ۵ Critical، ۲۲ High، ۸ Moderate و ۱ Low گزارش می‌کند. سبز بودن تست‌ها به معنی ممیزی امنیتی پاک یا تأیید مین‌نت نیست.

## اصلاح ابزار اجرا

- مسیر ثابت Node تنها انتخاب نیست: ابتدا `FTI_NODE_BINARY`، سپس runtime شناخته‌شده و سپس Node موجود در PATH بررسی می‌شود؛ Node 22 یا جدیدتر لازم است.
- تست در پوشهٔ تازه با دسترسی 0700، HOME و TMPDIR مستقل اجرا می‌شود. متغیرهای محیطی کیف‌پول، RPC، fork، تنظیم تولید، توکن npm و preloadهای Node به فرایند تست منتقل نمی‌شوند. این جداسازی محیط است، نه sandbox سیستم‌عامل یا شبکه؛ فقط commit بررسی‌شده اجرا شود.
- دریافت Git به SHA کامل و غیرقابل‌تغییر محدود است و شناسهٔ checkout دوباره کنترل می‌شود؛ ابزار به باقی‌ماندن نام شاخه وابسته نیست.
- نصب، کامپایل، همهٔ تست‌ها و build وب در `verification.log` ثبت می‌شوند. `result.json` شامل commit، مرحله، نتیجه و exit code است. شکست هر مرحله خروجی موفق تولید نمی‌کند.

## اعتبارسنجی این اصلاح

در همین محیط ۱۴ تست orchestration با git/npm/node شبیه‌سازی‌شده اجرا شد: همه موفق و صفر شکست/skip/cancel. بررسی `bash -n` و `node --check` نیز موفق بود. این ۱۴ تست، اجرای دوبارهٔ Solidity/EVM نیستند. دسترسی شبکهٔ محیط محلی برای clone مخزن برقرار نبود؛ کل تست‌های قراردادهای این شاخه در این محیط دوباره اجرا نشده‌اند.

## اجرای سرور

فایل اصلاح‌شدهٔ `tools/test-continuity-transfer.sh` را با SHA کامل نسخهٔ بررسی‌شده اجرا کنید:

```bash
bash tools/test-continuity-transfer.sh b254a379b08929a261dccfeae18bcf17d3781b90
```

این فرمان فایل‌های همان SHA را در پوشهٔ ایزوله دریافت و تست می‌کند؛ روی checkout فعلی پروژه نوشته نمی‌شود. برای تست شاخهٔ جدید، به‌جای SHA بالا، SHA کامل همان نسخهٔ بررسی‌شده را قرار دهید. گزینهٔ مسیر متفاوت Node، در صورت نیاز:

```bash
FTI_NODE_BINARY=/absolute/path/to/node bash tools/test-continuity-transfer.sh FULL_REVIEWED_COMMIT_SHA
```

ابتدای خروجی `FTI_RESULT_DIR=...` مسیر گزارش را نشان می‌دهد. موفقیت فقط پس از پایان تست و build با `TRANSFER_VERIFICATION_PASS` مشخص می‌شود. قطع SSH می‌تواند اجرای foreground را قطع کند؛ برای اجرای مستقل از SSH از یک نشست مدیریت‌شدهٔ سرور استفاده شود. این ابزار خودش کار را به پس‌زمینه نمی‌فرستد.

## مرز ارتقا و مهاجرت

مسیر فعلی برای حفظ کاربران و موجودی‌ها، ارتقای سازگارِ implementation در همان آدرس‌های proxy با حاکمیت ۵ از ۷ و timelock واقعی ۷۲ ساعته است. فایل `verify-continuity-transition.mjs` عمداً تغییر آدرس proxy را رد می‌کند. انتقال به آدرس مستقل به importer کامل، پشتوانهٔ منتقل‌شده، جلوگیری از اجرای دوباره، بازنشسته‌کردن مبدأ و راستی‌آزمایی جداگانه نیاز دارد و هنوز در این نسخه عرضه نشده است.

هیچ تراکنش عمومی، رأی شورا، تغییر implementation یا انتقال موجودی در این ادامه انجام نشده است. نتیجهٔ CI و آزمایش محلی را جایگزین تأیید وضعیت واقعی قراردادهای نصب‌شده نکنید.
