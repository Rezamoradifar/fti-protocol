# اتصال وب به قراردادهای اصلی

هر هفت تراکنش در خروجی مستقل `finalize-mainnet.mjs` تأیید شدند. تنظیمات عمومی، رسیدها و آدرس‌ها در `deployments/mainnet-20261016.json` ثبت‌اند. بلوک بررسی 127910644 و حداقل تأیید رسیدها ۱۲ است. source قراردادها و runtime دقیقاً `ba82373a83d63fba0643332371cfb6d62903c849` است؛ تغییرات بعدی ابزار نصب، نسخهٔ قراردادها را عوض نمی‌کنند.

## اجرای اپراتور

از checkout پین‌شدهٔ ابزار جدید، `bash tools/connect-mainnet-web.sh` را به‌عنوان root روی VPS موجود اجرا کنید. ابزار checkout قبلی `/var/tmp/fti-metamask-release.DkBBCLZm` را از نظر revision و پاک‌بودن تغییرات tracked بررسی می‌کند، وابستگی‌ها و خروجی‌های ساخت را بازسازی کرده و RPC اصلی را بدون نمایش روی ترمینال می‌گیرد. کلید خصوصی لازم نیست. در صورت نبود این مسیر یا تفاوت runtime، ابزار متوقف می‌شود؛ مسیرهای سرور را حدس نمی‌زند.

وب قبلی تا پایان بررسی قراردادها فعال می‌ماند. runtime در یک release جدا ذخیره می‌شود و fingerprint، کد قراردادها، شبکه، نقش‌ها و دسترسی واقعی کاربر سرویس بررسی می‌شوند. فایل محیط قبلی و واحد systemd خصوصی بکاپ می‌شوند. فقط override جدید `zzz-fti-mainnet-web.conf` برای وب ساخته می‌شود. پورت ۳۱۱۰ حفظ می‌شود؛ Nginx تغییر نمی‌کند.

موفقیت مستلزم سلامت شبکهٔ ۵۶، تطبیق تنظیمات، مدل استخر و بایت‌های فایل‌های وب و تمام assetهای هش‌شده روی localhost و HTTPS دامنه است. در شکست، override متعلق به این نصب حذف و وب قبلی شروع می‌شود. فرمان rollback پیش از تغییر چاپ می‌شود؛ در صورت ویرایش هم‌زمان override، ابزار آن ویرایش را حفظ و برای بررسی دستی متوقف می‌شود. این بازگشت فقط سرویس وب را برمی‌گرداند؛ تراکنش‌های زنجیره قابل بازگردانی نیستند.

`FTI_MAINNET_WEB_ACTIVE` فقط اتصال وب و بررسی HTTP را اعلام می‌کند. پنج آزمون محلی pin شبکه/آدرس، حذف کلید و RPC تست‌نت از محیط وب، rollback شکست HTTPS، حفظ ویرایش هم‌زمان و بازگشت override موفق شدند. این آزمون‌ها اجرای روی VPS نیستند.

Keeper قبلی تغییر نمی‌کند و Keeper مین‌نت هنوز راه‌اندازی یا تأیید نشده است. بررسی بصری دامنه و موبایل پس از خروجی نصب لازم است. این تغییر هیچ قرارداد، منطق اقتصادی، چیدمان یا موجودی را تغییر نمی‌دهد و هیچ تراکنشی ارسال نمی‌کند.
