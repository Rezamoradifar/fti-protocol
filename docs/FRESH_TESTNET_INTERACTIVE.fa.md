# اجرای تعاملی دیپلوی تازه روی BNB Testnet

این ابزار فقط مسیر عمومی BNB Testnet با chainId=97 را می‌پذیرد؛ یک Ganache محلی با شناسه 31337 را به‌جای تست‌نت عمومی قبول نمی‌کند. قراردادها از نسخهٔ ثابت `81aae37e2ad3abcbe46d27ad48c8f89ba54610d5` ساخته می‌شوند. همان کد اقتصادی آزموده‌شده استفاده می‌شود؛ کاربران، موجودی‌ها، deployment و سرویس‌های قبلی خوانده یا جابه‌جا نمی‌شوند.

**وضعیت تحویل:** runner در گیت‌هاب منتشر شده است، نه اینکه قراردادهای تازه روی شبکه عمومی ساخته شده باشند. دستیار به امضاکننده یا ترمینال VPS کاربر متصل نیست. اپراتور باید این فرمان را در همان ترمینال تعاملی اجرا و برنامهٔ استقرار را تأیید کند.

## پیش‌نیاز

ولت آزمایشی دارای tBNB، آدرس عمومی همان ولت، هفت آدرس عمومی منتخب شورا، و فایل خصوصی کلید دیپلوی‌کننده روی خود سرور لازم‌اند. ابزار آدرس‌های شورا یا کلیدهایشان را خودکار انتخاب یا ایجاد نمی‌کند و تنظیمات شورای قبلی را پیش‌فرض نمی‌گیرد. فایل کلید باید متعلق به کاربر اجراکننده، بدون symlink/hardlink و با دسترسی 0600 یا 0400 باشد. **خود کلید یا عبارت بازیابی را در چت، آرگومان ترمینال، log یا گیت‌هاب نگذارید.** ابزار فقط مسیر فایل را می‌پرسد.

Python 3، Bash، Git، curl و Node 22+ مورد نیازند. runtime شناخته‌شدهٔ پروژه بررسی می‌شود؛ گزینهٔ `--node` هم مسیر مطلق Node موجود را می‌پذیرد و runtime سرویس فعلی را عوض نمی‌کند. ابتدا RPC، گس و ورودی‌ها بررسی می‌شوند، سپس نصب وابستگی‌های قفل‌شده، کامپایل، ساخت و ۶۲ تست هدفمند نسخهٔ پایه در checkout تازه اجرا می‌شوند.

## اجرا

```bash
(
  set -euo pipefail
  umask 077
  REV='6fa21acd21e2ea3ecbd68d6814804558eb31a487'
  FILE="$(mktemp /root/fti-testnet-runner.XXXXXX.py)"
  curl -fL --retry 2 --connect-timeout 15 --max-time 120 \
    "https://raw.githubusercontent.com/Rezamoradifar/fti-protocol/$REV/tools/start-fresh-testnet.py" \
    -o "$FILE"
  printf '%s  %s\n' \
    '411fd980aa4d221b91c4b3928382fa4a0d2254dd775ea1e75503ff0a6293bbde' \
    "$FILE" | sha256sum -c -
  printf '\nRUNNER_SAVED=%s\n' "$FILE"
  python3 -I -u "$FILE"
)
```

روی سؤال RPC با Enter از endpoint عمومی رسمی استفاده می‌شود؛ RPC خصوصی را هم فقط در ورودی پنهانِ ترمینال می‌توان داد. endpoint به‌صورت پیش‌فرض این است: `https://bsc-testnet-dataseed.bnbchain.org`؛ شبکه در زمان اجرا با eth_chainId کنترل می‌شود، نه با اعتماد به نام URL.

بودجهٔ کل گس با واحد tBNB و سقف قیمت گس با واحد gwei گرفته می‌شود، بدون عدد پیش‌فرض. تبدیل اعداد اعشاری دقیق و بدون float است. موجودی باید حداقل برابر بودجه‌ای باشد که خود اپراتور انتخاب کرده است؛ این عدد برآورد هزینهٔ نهایی نیست. گس جاری بالاتر از سقف و تراکنش معلق باعث توقف می‌شوند.

`TEST-GENESIS` پذیرش ساخت ۳۱ جایگاه آزمایشی تازهٔ بدون خرید است، نه ورود ۳۱ کاربر قدیمی. کلیدهای ۳۰ ولت کمکی تازه فقط توسط ابزار اصلی در فایل محلی خصوصی نگهداری می‌شوند؛ کلیدهای شورای جدید ساخته نمی‌شوند.

قبل از هر ارسال، برنامهٔ کامل در plan.json نوشته و خلاصهٔ عمومی، آدرس‌های شورا، بودجه و digest نمایش داده می‌شوند. آدرس‌ها در این مرحله **پیش‌بینی‌شده و هنوز دیپلوی‌نشده** هستند. پس از بررسی برنامه، عبارت دقیق `DEPLOY 97` به‌علاوهٔ digest همان برنامه باید در ترمینال وارد شود. پاسخ دیگر به معنی لغو است. برنامهٔ اصلی هنگام اجرا نیز محتوا، nonce، امضاکننده و شبکه را دوباره بررسی می‌کند.

## توقف، نتیجه و محدوده

هفت ایجاد قرارداد و یک bind، هشت تراکنش جدا هستند. خطا یا قطع ارتباط می‌تواند قراردادهای تازهٔ نیمه‌تمام و گس مصرف‌شده باقی بگذارد؛ بنابراین ارسالِ دوباره خودکار نیست. نشانگر `deployment-requested.json` در `$HOME/fti-fresh-testnet-runner/` پیش از مرحلهٔ ارسال ثبت و پس از خطا یا موفقیت حفظ می‌شود. آن را برای تکرار کورکورانه پاک نکنید. مسیر دقیق خروجی و source در آن ثبت می‌شود؛ journal ابزار اصلی را بررسی کنید. فایل `deployment.started.json` اصلی نیز همچنان برقرار است.

تنها نتیجهٔ نهایی `FTI_FRESH_TESTNET_DEPLOYED` بعد از تأیید ایجاد و حالت اولیه، آدرس‌های قرارداد ساخته‌شده را اعلام می‌کند. مسیر result.json با `VERIFIED_RESULT` چاپ می‌شود. فایل source checkout و خروجی خصوصی را نگه دارید. فقط result.json عمومی را برای بررسی بفرستید، نه test-genesis-keys.json یا فایل کلید.

این ابزار سایت، nginx، Keeper و پورت‌های ۳۱۱۰/۳۱۰۸ را تغییر نمی‌دهد. اتصال فرانت نصب‌شده به آدرس‌های تازه، مرحلهٔ بعد از رسیدهای معتبر دیپلوی است. موفقیت دیپلوی به معنی آماده‌بودن مین‌نت، تکمیل تمام ترجمه‌ها یا ممیزی مستقل نیست. پشتوانه MockUSD آزمایشی است، نه USDT واقعی.

## شواهد همین ادامه

بایت‌های runner منتشرشده با Git blob برابر `332d200b217e0f7d4a2c20748e7edcb5894e263a` و SHA-256 فرمان بالا برابرند. Python syntax و ۲۰ تست محلیِ سیاست ورودی/بودجه/تأیید/عدم تکرار موفق شدند. RPC و ارسال در این ۲۰ تست شبیه‌سازی‌شده بودند؛ این‌ها تست EVM یا رسید شبکه عمومی نیستند. فایل این مجموعهٔ ۲۰تایی هنوز در مخزن منتشر نشده و CI آن ادعا نمی‌شود. ۶۲ تست قبلی استقرار تازه و کنترل‌های بیلدر متعلق به نسخهٔ پایه و اجرای مستقل قبلی‌اند؛ موفقیت runner روی VPS و دیپلوی تازهٔ عمومی در این نوبت مشاهده نشده است.

مرجع endpoint: مستندات رسمی BNB Chain، بخش BSC JSON-RPC Endpoint: https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/
