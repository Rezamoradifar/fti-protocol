# فلش تعادل بالاتر از سقف ساعتی FTI

وضعیت: تغییر منبع در شاخه جدا؛ بدون تغییر قرارداد یا موجودی شبکه زنده. مبنا، نسخه `95f753f7c4089e8a5401f2ffb3f8a1bd8e567f42` از PR #32 است و تغییر جانمایی آن حفظ شده است.

## قاعده تأییدشده کاربر

در ۱۳ اکتبر ۲۰۲۶ کاربر تأیید کرد: راست ۲۰، چپ ۱۵، سقف ۵؛ با اعتبار کافی، ۵ پوینت پرداخت شود، ۱۰ تعادل بالاتر از سقف بسوزد، چپ صفر و راست ۵ برای دوره بعد بماند. تنها اختلاف دو شاخه ذخیره می‌شود. هیچ مبلغ ثابت جدیدی برای هر پوینت تصویب نشده است.

```
raw = min(left, right)
candidate = min(raw, hourlyCap)
flushed = raw - candidate
paid = min(candidate, floor(attributedBudget / 20))
consumed = paid + flushed
leftAfter = left - consumed
rightAfter = right - consumed
```

مبنای بودجه و گردکردن اتمی همان قرارداد قبلی است. اگر `paid == candidate` باشد، کل دست کوچک تسویه و اختلاف دست بزرگ ذخیره می‌شود. شرط کف پشتوانه ۲۰ تغییر نکرده است: تعادل داخل سقف که به علت کمبود تأمین مالی پرداخت نشده، همچنان می‌ماند. برای نمونه عمق ۱۰ با چپ ۱۵، راست ۲۰ و سقف ۵: بودجه ۹۰، پرداخت ۴ پوینت، فلش ۱۰، مانده چپ ۱ و راست ۶ است. این مانده، طلب نقدی تضمین‌شده نیست.

## اعتبار مربوط به فلش

اعتبارِ منتسب به تعادل بالاتر از سقف از دو شاخه کاربر و `assignedPointCredit` کم و به `retainedPointReserve` اضافه می‌شود. پول از قرارداد خارج نمی‌شود؛ مدیر، عضو جدید یا کاربر فعلی صاحب طلب تازه نمی‌شود. بودجه پرداختی نیز مثل قبل به نقد/اتوبای تبدیل می‌شود. حسابداری حفظ می‌شود:

```
pointPool = queuedPointCredit + assignedPointCredit + retainedPointReserve
actualUSD >= pointPool + builderAccounted + totalPending + totalAuto
```

رویداد `HourlyCapFlushed(epoch, wallet, points, retainedCredit)` مقدار سوختن حجم و اعتبار نگهداری‌شده را قابل پیگیری می‌کند. ثابت `hourlyCapFlushVersion = 1` قابلیت نسخه را برای API معرفی می‌کند. API فقط پس از پاسخ موفق قرارداد، قانون جدید را در رابط نشان می‌دهد؛ وجود ABI به‌تنهایی اثبات فعال‌سازی نیست.

## موارد حفظ‌شده

سقف‌های رتبه/حفاظت، محاسبه ارزش پوینت، مرز حفاظت ۱۶، حداقل پشتوانه ۲۰، سهم‌های ۹۰/۵/۴/۱، حجم تاریخی و آستانه رتبه، مطالبات قبلی، اتوبای، صندوق‌های ماهانه، توکن، شورا و Timelock تغییر نکرده‌اند. هیچ فیلد ذخیره‌سازی اضافه یا جابه‌جا نشده است. قراردادهای قدیمی `FundedBinaryPlan` و `FundedBinaryPlanFloor` عمداً دست‌نخورده‌اند؛ مسیر تازه از `FundedBinaryPlanUpgradeable` استفاده می‌کند.

## آزمون‌ها

آزمون جدید با خرید واقعی MockUSD روی Ganache، مثال تأییدشده و حالت معکوس، برابری شاخه‌ها، زیر سقف، تک‌شاخه، چهار رتبه بیلدر، تأخیر کمبود پشتوانه، گردکردن، اتوبای، مانده قوی و منع پرداخت تکراری را می‌سنجد. آزمون‌های قبلی که برای درآمد ساعت بعد به حجم اضافه رتبه‌گیری وابسته بودند، با خرید واقعی تازه تغذیه شده‌اند؛ کنترل‌های حفظ موجودی و پرداخت یک‌باره حذف نشده‌اند.

نتایج اجرای واقعی در `HOURLY_CAP_FLUSH_VALIDATION_20261013.md` ثبت می‌شود. وجود فایل تست به‌تنهایی ادعای قبولی نیست.

## مرز فعال‌سازی

این تغییر، نسخه قابل بررسی کد است؛ مرج PR، اجرای دستور وب یا تعویض ABI به معنی تغییر قرارداد نیست. روی اجرای عمومی ۱۰۰ ولتی جاری چیزی نصب نشده است. فعال‌سازی بعدی به شناسایی نسخه زنده، پایان صف حجم و تسویه ساعتی/ماهانه، snapshot، بررسی اقتصادی مانده‌های قبلی و مسیر مجاز حاکمیتی نیاز دارد. حجم انباشته قبلی در نخستین تسویه با منطق تازه مشمول قانون فلش می‌شود؛ برای آن معافیت پنهانی تعریف نشده است. مطلب و PDF قبلی که «مازاد سقف باقی می‌ماند» می‌گفت، توصیف نسخه قبلی است و نباید به‌عنوان مستند این نسخه ارائه شود.
