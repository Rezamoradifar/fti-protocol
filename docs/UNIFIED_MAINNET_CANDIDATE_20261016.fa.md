# نسخه یکپارچه آماده‌سازی دیپلوی FTI — ۱۶ اکتبر ۲۰۲۶

این نسخه روی PR #36 / `130b693459d51c33838b32444766a5d9adc30c80` ساخته شده و تنظیمات ولت PR #40 و لندینگ PR #39 را برای ساخت واحد جمع می‌کند. هیچ فایل Solidity و هیچ قانون اقتصادی تغییر نکرده است. قرارداد اجرایی شبکه اصلی از نوع Upgradeable است؛ تست قبلی ولت‌ها روی مدل قدیمی به‌تنهایی گواه آماده بودن این مدل نبود.

## تنظیمات قطعی

- شبکه مقصد BNB Mainnet، شناسه 56؛ شروع تازه، بدون مهاجرت کاربران/موجودی/پاداش/پوینت/Carry/Rank/Auto/بدهی تست‌نت.
- هر ۳۱ آدرس `config/v3-wallets.json` با ترتیب دقیق حفظ می‌شود. جایگاه اولیه واحد خرید، فعال‌سازی یا درآمد رایگان ندارد و از همان مسیر خرید کاربران فعال می‌شود.
- مالک `0x4B92747764E58C1F1Ad22E10a3D880fDD8Fc9d76` و توسعه‌دهنده `0x450AE539f93E10f748247D82822CcF0414dbE607` خارج از این جایگاه‌ها هستند.
- عنوان owner در تنظیمات به معنی ایجاد اختیار مدیریتی تک‌امضایی نیست؛ شورا ۵ از ۷ و قفل زمانی ۷۲ ساعت بدون تغییر حفظ شده‌اند.
- قالب مشخص `config/mainnet-approved-input.REQUIRED.json` آدرس‌های داده‌شده را دارد. CLI برنامه‌ریزی و تأیید رسیدها، همین پروفایل را الزام می‌کنند؛ متغیر ولت تست‌نت نمی‌تواند آن را جایگزین کند.
- برنامه‌ریز فقط هفت تراکنش بدون امضا می‌سازد: شورا، قفل زمانی، پیاده‌سازی توکن، پروکسی توکن، پیاده‌سازی باینری، پروکسی باینری و اتصال توکن/باینری. MockUSD روی شبکه اصلی ساخته نمی‌شود.

## ورودی‌های عمومی باقی‌مانده

کاربر USDT شبکه اصلی BNB را انتخاب کرد. آدرس 0x55d398326f99059fF775485246999027B3197955، نماد USDT و اعشار ۱۸ روی chain 56 خوانده شد؛ هش runtime و بلاک مشاهده در config/mainnet-usdt-collateral.json ثبت است. هفت آدرس شورا در ۱۶ اکتبر صریحاً توسط کاربر تأیید و با همان ترتیب در `config/mainnet-council.json` و ورودی شبکه اصلی ثبت شدند. آدرس عمومی دیپلوی‌کننده هنوز ارائه نشده است. آستانه ۵ از ۷ و قفل زمانی ۷۲ ساعت ثابت‌اند. گس BNB و نقش Keeper نیز در محیط امن سرور باید بررسی شوند. RPC دارای کلید و کلیدهای امضا نباید در GitHub یا چت ذخیره شوند.

## ساخت ورودی و برنامه بدون ارسال تراکنش

در checkout تمیز و پین‌شده، پس از `npm ci`، `npm ci --prefix landing`، `npm run compile`، `npm run build:web` و `npm run build --prefix landing`:

```sh
node scripts/create-mainnet-input.mjs \
  --deployer PUBLIC_DEPLOYER_ADDRESS \
  --out /PRIVATE/mainnet-input.json
```

بدون دو گزینه اختیاری collateral، همان USDT و هش پین‌شده نسخه انتخاب می‌شود. مقدار متفاوت در CLI رد می‌شود.

شورای تأییدشده به‌صورت پیش‌فرض بارگذاری می‌شود. گزینه اختیاری `--council-config` فقط همان هفت عضو با همان ترتیب و `threshold:5` را می‌پذیرد؛ برنامه‌ریز و بررسی‌کننده رسید نیز تغییر شورا را رد می‌کنند. ابزار، ۳۱ آدرس و دو نقش مستقل را از همین نسخه می‌گیرد؛ ولت تصادفی نمی‌سازد. خروجی قبلی را بازنویسی نمی‌کند. سپس RPC شبکه اصلی را فقط در ترمینال امن وارد کنید:

```sh
# File contains only the operator GetBlock endpoint; keep it private (mode 0600).
export FTI_MAINNET_RPC_FILE=/etc/fti/mainnet/getblock.rpc
node scripts/prepare-mainnet.mjs \
  --config /PRIVATE/mainnet-input.json \
  --out /PRIVATE/mainnet-plan.json
unset FTI_MAINNET_RPC_FILE
```

این مرحله فقط شبکه، بلاک، وثیقه ۱۸ اعشار، کد و nonce را می‌خواند و payload می‌سازد. امضا یا ارسال انجام نمی‌دهد؛ خروجی `readyToBroadcast:false` است. مبلغ گس واقعی به شرایط شبکه و برنامه نهایی بستگی دارد.

پس از امضای مستقل و اجرای دقیق تراکنش‌های بازبینی‌شده، `scripts/finalize-mainnet.mjs` هر هفت رسید را با برنامه، nonce، فرستنده، کد و شبکه تطبیق می‌دهد. تأیید اولیه روی بلاک مشخص، ترتیب ۳۱ جایگاه، واحد و سریال فعال‌سازی صفر، نبود مالک/توسعه‌دهنده در اعضا، عرضه/ذخیره صفر و نبود بدهی/پاداش واردشده را بررسی می‌کند. این ابزار هم امضا یا ارسال ندارد. سرویس‌های تست‌نت را تا تأیید قراردادها و تنظیمات جدید جابه‌جا نکنید.

## فرانت و نصب

- لندینگ جدید با فایل‌های هش‌شده و فونت محلی ساخته می‌شود. صفحات `/token-site/`، `/whitepaper/` و `/roadmap/` جدا و محفوظ‌اند؛ فایل‌های قدیمی لازم برای سایر سطوح حذف نشده‌اند.
- مسیر assets در سرور Node و MIME فونت اصلاح شده است. نشان mainnet فقط از تنظیمات سرویس می‌آید؛ صفحه معرفی به‌تنهایی ادعای شبکه اصلی نمی‌کند.
- `landing/install-dist.sh` پشتیبان و تعویض اتمیک/بازگردانی دارد. دستورالعمل `landing/README.md` را دنبال کنید و داخل docroot زنده build نگیرید.
- `tools/prepare-mainnet-candidate.sh FULL_SHA` نسخه پین‌شده را در پوشه مستقل می‌سازد و تست می‌کند؛ سرویس، پیکربندی فعال یا قرارداد عمومی را تغییر نمی‌دهد.

## مرز نتیجه

تست محلی chain ID 56، تراکنش واقعی BNB Mainnet نیست. اتصال RPC عمومی سایت در بررسی قبلی هنوز 97 بود. بدون اجرای برنامه نهایی، رسیدهای شبکه اصلی، راه‌اندازی Keeper، نصب نسخه و بررسی مرورگر روی دامنه، سایت راه‌اندازی‌شده یا mainnet فعال اعلام نمی‌شود. گواه ممیزی مستقل امنیتی هم در این آماده‌سازی صادر نمی‌شود.

## انتخاب USDT و RPC

آدرس و هش کد USDT در CLI ساخت ورودی، برنامه‌ریزی و تأیید نهایی پین شده‌اند. هش در زمان برنامه‌ریزی با کد شبکه دوباره مقایسه می‌شود. سند مشاهده از RPC عمومی BNB تهیه شده و اثبات اتصال به GetBlock کاربر نیست. URL قبلی GetBlock در زمینه بازیابی‌شده ماسک شده بود؛ اتصال واقعی تا قرارگرفتن آن در فایل خصوصی سرور تأیید نشده است. فایل نمونه محیط سرور، Keeper و مانیتور همگی از FTI_MAINNET_RPC_FILE پشتیبانی می‌کنند؛ تنظیمات تست‌نت خودکار به شبکه اصلی منتقل نمی‌شوند.

طبق تصمیم قبلی کاربر، پس از تکمیل ورودی‌ها ابتدا تمرین نهایی عمومی تست‌نت و سپس همان SHA بدون تغییر برای شبکه اصلی لازم است. تست محلی جای آن مرحله را نمی‌گیرد.
