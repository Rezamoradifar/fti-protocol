# اصلاحات اتوبای و بستن ماه — کاندید انتشار

مبنای این تغییر، شاخهٔ `feat/global-builder-controls-20261011` و commit برابر `4e720d7b11c4b2b2c3f51b775b485a5f4c0e9856` در مخزن اصلی FTI است. کد از patch مرحلهٔ قبل وارد شده و دوباره آزموده شده است. این سند گزارش اجرای مهاجرت یا فعال‌سازی سایت نیست.

## تغییرات تحویل‌شده

در `FundedBinaryPlanUpgradeable` درصد انتخابی صحیح ۵ تا ۱۰۰ با تابع `setAutoBuyPercent(bool,uint8)` اضافه شده است. حساب‌های موجود با مقدار پیش‌فرض ۵٪ ادامه می‌دهند. mapping جدید انتهای storage است؛ ساختار Member و همهٔ متغیرهای قدیمی، از جمله maxAutoPrice، جابه‌جا یا حذف نشده‌اند. تابع قدیمی `setAutoBuy(bool,uint256)` برای سازگاری ABI باقی است، ولی پارامتر سقف قیمت دیگر اثری ندارد و به درصد تبدیل نمی‌شود.

سهم اتوبای فقط از پاداش ساعتی باینریِ حساب واجد رتبه تأمین می‌شود. جمع سهم نقدی و اتوبای برابر پاداش ناخالص همان تخصیص است. انتخاب ۱۰۰٪ مطالبات نقدی قبلی را پاک نمی‌کند؛ تغییر ترجیح فقط روی تخصیص‌های بعدی اثر دارد. تغییر ترجیح حین تسویهٔ ساعتی ممنوع است. درآمد صندوق ماهانهٔ Builder وارد اتوبای نمی‌شود.

سقف قیمت هر توکن برای اتوبای حذف شده، نه کارمزد، مجوز خرید، موجودی، freeze یا حداقل خروجی. quote و خرید در همان تراکنش انجام می‌شوند. Keeper مانده‌های بزرگ را در دسته‌های کامل حداکثر ۶۴٬۰۰۰ دلار آزمایشی، مطابق محدودیت توکن فعلی، پردازش می‌کند؛ این محدودیت اندازهٔ تراکنش است، نه قیمت هر FTI.

فراخوانی زودهنگام `beginBuilderMonth` فقط رویداد درخواست با موعد ثابت ثبت می‌کند. هیچ‌کدام از چهار صندوق زودتر بسته یا تقسیم نمی‌شوند. موعد ساعت ۰۰:۰۰ UTC روز اول ماه میلادی بعد است، نه ۳۰ روز بعد از کلیک. پردازش ساعتی نیز باید به همان مرز رسیده باشد. Keeper پردازش ماه آماده را بر صف نقدی مقدم می‌کند. اجرای واقعی نیازمند Keeper روشن، گس و RPC است؛ پایان همهٔ دسته‌ها دقیقاً در همان ثانیه تضمین نمی‌شود.

API، فرم درصد و متن پنل با قابلیت قرارداد هماهنگ شده‌اند. رابط مدل قدیمی حفظ شده است. ابزار استخراج و migration mapping جدید درصد را می‌شناسد؛ snapshot و manifest قبلی نباید برای چیدمان جدید استفاده شوند. ترجمهٔ کامل هفت زبان، لینک‌های شبکه‌های اجتماعی و اصلاح نمودار در این بسته انجام نشده‌اند.

## شواهد بازاجرای محلی

کامپایل Solidity، ساخت وب و مقایسهٔ storage موفق شدند. runtime باینری ۲۳٬۹۰۳ بایت است. اجرای هدفمند زیر در محیط محلی Node 22.16.0 با وابستگی‌های قفل‌شده و Ganache موفق شد:

```bash
node --test --test-concurrency=3 test/global-builder-controls.test.mjs test/funded-keeper.test.mjs test/continuity-deployment.test.mjs test/continuity-upgrade.test.mjs test/address-migration*.test.mjs
```

نتیجه: ۳۹ تست، ۳۹ موفق، صفر شکست، لغو و حذف؛ مدت گزارش‌شده 181910.932172 میلی‌ثانیه. این اجرای واقعی قراردادهای آزمایشی روی EVM محلی است، نه وضعیت کاربران عمومی. آزمون‌های درصد، مطالبات، ماه میلادی، Keeper، حفظ وضعیت و مهاجرت در این مجموعه‌اند؛ کل مجموعهٔ تست پروژه دوباره اجرا نشده است.

علاوه بر آن، `node --test test/builder-installer.test.mjs` با ۱۰ تست موفق و صفر شکست/لغو/حذف پایان یافت. این ده مورد فقط orchestration اسکریپت با git/npm/node ساختگی‌اند، نه ده تست قرارداد. `bash -n tools/prepare-builder-controls.sh` نیز موفق بود. JSON چیدمان جدید فقط از نظر فاصله‌گذاری فشرده شده و دادهٔ آن با خروجی کامپایل مقایسه می‌شود.

## نصب جداگانه از سرویس فعلی

`tools/prepare-builder-controls.sh` فقط یک SHA کامل بررسی‌شده را می‌پذیرد. کد را در پوشهٔ تازهٔ `$HOME/fti-candidates/builder-XXXXXXXX/source` دریافت می‌کند، هویت commit را کنترل می‌کند، وابستگی‌ها را نصب و قرارداد، storage، تست‌ها و وب را بررسی می‌کند. HOME موقت و محیط تمیز مانع ارث‌بری متغیرهای کلید/RPC تولید می‌شوند؛ این جداسازی محیط، sandbox سیستم‌عامل نیست.

```bash
bash tools/prepare-builder-controls.sh FULL_REVIEWED_COMMIT_SHA
```

Node حداقل ۲۲ لازم است. مسیر شناخته‌شدهٔ Node سرور بررسی می‌شود و در نبود آن از PATH استفاده می‌شود؛ مسیر صریح با `FTI_NODE_BINARY` پذیرفته می‌شود. مسیر `FTI_CANDIDATE_DIR` ابتدای اجرا چاپ می‌شود. تمام خروجی در `install.log` و نتیجه در `result.json` ثبت می‌شود. هر شکست اجرا را متوقف می‌کند. این فرایند foreground است؛ قطع SSH ممکن است آن را متوقف کند.

موفقیت فقط با `FTI_BUILDER_CANDIDATE_PREPARED` مشخص می‌شود. مقدار `liveActivated` و `fundsMoved` در نتیجه همواره false است. اسکریپت هیچ systemd، nginx، deployment فعلی، آدرس پروکسی، کاربر یا موجودی زنده را تغییر نمی‌دهد. اجرای آن مساوی نمایش اصلاحات روی سایت نیست.

## فعال‌سازی زنده، جدا از نصب کد

این تغییر شامل منطق قرارداد است. ارتقای implementation باید با چیدمان سازگار، حاکمیت موجود و توقف/راستی‌آزمایی لازم انجام شود؛ سپس وب و Keeper باید با هویت انتشار و اطلاعات نصب صحیح هماهنگ شوند. کپی‌کردن فایل‌ها روی release قدیمی یا حذف کنترل sourceFingerprint/codeHash راه فعال‌سازی مجاز نیست. برای حفظ کاربران نباید نصب Genesis تازه را جای ارتقا یا مهاجرت گرفت.

هیچ تراکنش عمومی، رأی شورا، انتقال پول یا فعال‌سازی سرور در این انتشار انجام نشده است. ممیزی مستقل، QA مرورگر و آزمایش شبکهٔ عمومی تأیید نشده‌اند. نتیجهٔ CI همان commit را مستقل از شواهد محلی بررسی کنید؛ موفقیت تست، ممیزی امنیت یا تأیید مین‌نت نیست.
