# انتشار خودکار کانال FTI

این بسته برای یک کانال عمومی تحت مدیریت صاحب پروژه است. نام کانال پیشنهادی `FTI Protocol | فارسی` و نام کاربری پیشنهادی `FTIProtocol_FA` است. هیچ نام کاربری رزرو نشده و ساخت کانال یا انتشار زنده در مرحله آماده‌سازی کد انجام نشده است. لینک فعلی تلگرام سایت بدون تأیید مالکیت تغییر نمی‌کند.

## آماده‌سازی در تلگرام

1. در حساب خودتان کانال بسازید و آدرس عمومی آن را ثبت کنید. اگر تلگرام نام پیشنهادی را نپذیرفت، نام آزاد دیگری متعلق به پروژه انتخاب کنید.
2. در `@BotFather` دستور `/newbot` را بزنید. نام پیشنهادی ربات `FTI Publisher` و نام کاربری پیشنهادی آن `FTIProtocol_PublisherBot` است؛ پذیرش هر نام را تلگرام تعیین می‌کند.
3. ربات را در کانال، ادمین با اجازه `Post Messages` کنید. این ناشر به مجوز حذف پیام، افزودن مدیر یا دسترسی به کیف‌پول نیاز ندارد.
4. توکن BotFather را فقط در ترمینال سرور وارد کنید. در چت، مخزن، خط فرمان، فایل عمومی یا پیام کانال قرار ندهید.

کانال و نام کاربری آن در حساب تلگرام صاحب پروژه ساخته می‌شوند. ربات وظیفه انتشار محتوا در کانالی را دارد که قبلاً به آن دسترسی داده شده است.

## نصب روی VPS

نیازمندی: Python 3.10 یا جدیدتر، پایگاه زمانی `Asia/Tehran`، systemd با پشتیبانی از `LoadCredential` و دسترسی HTTPS به `api.telegram.org`.

فایل `tools/install-telegram-publisher-release.py` مستقل است و کد ناشر و ۱۰ پست آماده را داخل خود دارد. قبل از اجرای فایل دریافتی، SHA-256 آن را با نسخه ارائه‌شده تطبیق دهید.

نمایش برنامه بدون درخواست توکن، تغییر سرویس یا ارسال پیام:

```bash
python3 tools/install-telegram-publisher-release.py
```

نصب با دسترسی root روی VPS؛ به‌جای نمونه، نام واقعی کانالی را قرار دهید که مدیریت آن دست شماست:

```bash
python3 tools/install-telegram-publisher-release.py --apply --channel @YOUR_OWNED_CHANNEL
```

توکن با ورودی مخفی دریافت می‌شود. پیش از نصب، شناسه ربات، شناسه عددی کانال و اجازه ارسال بررسی می‌شود. شناسه عددی مقصد در تنظیمات ثابت می‌شود تا تغییر مالکیت یک نام کاربری، مقصد انتشار را عوض نکند. فایل تنظیمات فقط برای root خواندنی است و systemd آن را به‌عنوان credential در اختیار سرویس محدودشده می‌گذارد.

نصب، سرویس مستقل `fti-telegram-publisher.service` و تایمر آن را اضافه می‌کند. سرویس وب، قراردادها و Keeper تغییر یا ری‌استارت نمی‌شوند. بررسی اولیه سرویس با `--validate` فقط خواندنی است؛ هیچ پست آزمایشی نمی‌فرستد. هر بار اول ناشر نیز فقط صف را مسلح می‌کند و چیزی نمی‌فرستد.

پیش‌فرض: اولین پست فردا ساعت ۱۹ تهران و سپس روزی یک پست، در مجموع ۱۰ پست. این بسته متن تازه تولید نمی‌کند و پست‌های قبلی را تکرار نمی‌کند؛ ادامه انتشار به افزودن محتوای جدید به صف نیاز دارد. تاریخ دلخواه باید صریح و در آینده باشد؛ برای نمونه قالب `--first-at 'YYYY-MM-DDT19:00:00+03:30'`.

## مشاهده و توقف

```bash
systemctl status fti-telegram-publisher.timer --no-pager
journalctl -u fti-telegram-publisher.service -n 30 --no-pager
```

مسیر فایل صف در خروجی نصب با `QUEUE=` چاپ می‌شود. گزارش انتشار در SQLite زیر `/var/lib/fti-telegram/` نگهداری می‌شود. این گزارش را هنگام توقف، تغییر ربات یا به‌روزرسانی پاک نکنید؛ جلوگیری از ارسال تکراری به آن وابسته است.

توقف انتشار و حفظ صف و گزارش:

```bash
systemctl disable --now fti-telegram-publisher.timer
systemctl stop fti-telegram-publisher.service
```

راه‌اندازی مجدد:

```bash
systemctl enable --now fti-telegram-publisher.timer
```

نصب مجدد روی فایل تنظیمات، سرویس یا گزارش موجود انجام نمی‌شود؛ ابتدا وضعیت موجود باید بررسی شود.

## رفتار در قطعی

- شناسه و محتوای هر پست در گزارش پایدار ثبت می‌شود. اجرای هم‌زمان قفل می‌شود.
- اگر پاسخ ارسال نامشخص باشد یا پردازش وسط ارسال قطع شود، همان پست خودکار دوباره ارسال نمی‌شود و برای بررسی نگه داشته می‌شود. این روش ممکن است پستی را نفرستاده نگه دارد، اما از تکرار ناخواسته پس از قطع اتصال جلوگیری می‌کند.
- فقط پاسخ صریح محدودیت ۴۲۹ تلگرام، پس از زمان انتظار، امکان تلاش دوباره دارد.
- پستی که بیش از دو ساعت از موعد آن گذشته باشد خودکار جبران نمی‌شود. پس از قطعی طولانی، چند پست پشت سر هم منتشر نمی‌شود.
- سقف انتشار بر اساس روز واقعی تلاش ارسال در تهران محاسبه می‌شود.

## بررسی انجام‌شده

```bash
python3 test/telegram-publisher.test.py -v
python3 test/telegram-installer.test.py -v
python3 tools/install-telegram-publisher-release.py
```

آزمون‌های ناشر از پاسخ‌های شبیه‌سازی‌شده استفاده می‌کنند؛ ربات واقعی یا API ارسال زنده در تست فراخوانی نمی‌شود. مجوزهای فایل روی دیسک و تعریف سرویس نیز بررسی می‌شوند. نصب systemd و ارسال واقعی کانال تا ورود توکن و اجرای نصب روی VPS انجام نشده است.
